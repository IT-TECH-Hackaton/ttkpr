# Чем мы выделяемся и что дальше

Документ для команды: какие фичи делают «Карту пространства» заметно сильнее типового решения кейса, что уже готово на бэкенде и в общих пакетах, что осталось нарисовать во фронте и как всё это показать жюри.

## 1. Принципы

- **Организатору хватает телефона.** План — из картинки или видео, панорамы — из видео или серии кадров, точки — прямо в панораме.
- **Посетитель не ждёт.** Карта — статические файлы с CDN, маршруты считаются на телефоне, всё работает офлайн.
- **Площадка живая.** Расписание, статусы мест и объявления меняются без перепубликации.
- **Карта выглядит как у организатора.** Свой цвет, логотип и приветствие, встраивание на сайт.

## 2. Кастом помещений и посещения

| Фича                            | Зачем                                                       | Данные / API                                                             | Фронт                                    |
| ------------------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------ | ---------------------------------------- |
| Окна                            | реалистичный 3D и макет, окна не считаются проходом         | `openings[].category = "window"`, `sillHeightM`, `heightM`               | символ окна на плане, проём в 3D         |
| Доступ дверей и комнат          | служебные и закрытые не попадают в маршрут                  | `openings[].access`, `units[].access`                                    | значок «служебный», серый цвет           |
| Мебель и стенды как препятствия | маршрут огибает столы и стенды, а не идёт сквозь            | `fixtures[]`                                                             | контуры на плане, объём в 3D             |
| Зоны                            | «фудкорт», «зона тишины» внутри зала                        | `zones[]`                                                                | подписи и заливка                        |
| Удобства                        | «где розетка / вода / тихо / доступно»                      | `units[].amenities`                                                      | фильтр-чипы в поиске                     |
| Фото, ссылки, контакты, часы    | карточка места как мини-сайт                                | `photos`, `links`, `contacts`, `hours`                                   | галерея, кнопки                          |
| Расписание                      | «сейчас на сцене», «через 20 минут — питчи»                 | `pois[].events`, `eventsAt()`                                            | вкладка «Программа», бейдж «идёт сейчас» |
| Объявления                      | «обед в 13:00», «гардероб закрыт»                           | `venue.announcements`, `activeAnnouncements()`                           | баннер                                   |
| Живые статусы мест              | очередь в кафе, «открыто / занято / закрыто» без публикации | `PUT /api/maps/{id}/live/{poi}`, `GET /api/public/maps/{slug}/live.json` | цветная точка, опрос раз в 30 с          |
| Брендинг                        | карта выглядит как у организатора                           | `venue.branding`                                                         | CSS-переменные акцента, логотип          |
| Свои категории                  | «партнёр», «food truck»                                     | `venue.categories`, `categoryOf()`                                       | иконки и цвета                           |
| Языки                           | иностранные гости                                           | `translations`, `localized()`                                            | переключатель языка                      |

## 3. Съёмка по видео

| Режим             | Как снимать                                                         | Что получается                                 | Статус                                                           |
| ----------------- | ------------------------------------------------------------------- | ---------------------------------------------- | ---------------------------------------------------------------- |
| Панорама из видео | встать в центре и медленно повернуться на 360°, телефон вертикально | equirect → тайлы, как у фото-съёмки            | воркер `stitch_video`, API `POST /api/maps/{id}/panoramas/video` |
| Скан комнаты      | обойти комнату по периметру, камера на уровне груди                 | контур пола в метрах, высота стен, путь камеры | воркер `scan_room`, API `POST /api/maps/{id}/scans`              |
| Дальше (GPU)      | то же видео                                                         | плотная 3D-модель, Gaussian Splatting          | см. [VIDEO_TO_ROOM.md](VIDEO_TO_ROOM.md)                         |

Телефон присылает видео (WebM/MP4) и, если есть, дорожку ориентации из `DeviceOrientationEvent`. С ней точнее ориентация и масштаб.

## 4. Скорость и безопасность

- Опубликованный бандл — статический файл `/media/maps/{map_id}/v/{n}/bundle.json`, Caddy отдаёт его и тайлы сам, без Python, с кэшем «навсегда». Манифест — с ETag и 304.
- Статика сжата заранее (brotli 11 + gzip), HTTP/3.
- CSP с хешами inline-скриптов (генерируется при сборке образа), COOP для студии, запрет встраивания студии.
- CSRF по Origin для всех изменяющих запросов (в том числе вход), лимиты в Redis общие для всех процессов API.
- Блокировка строки при загрузке кадров, лимит размера черновика, видео до 300 МБ потоком на диск.
- Лимиты памяти контейнеров, бэкап базы раз в сутки, скрипт закалки сервера (fail2ban, автообновления).

## 5. Сценарий показа жюри (5 минут)

1. Телефон: стартовая страница → «Экскурсия по площадке»: маршрут через двор во второй корпус, проход по панорамам.
2. QR «Вы здесь» на столе жюри → «Маршрут сюда» до кофе, «Без ступенек» — путь через лифт.
3. Самолётный режим → карта и панорамы открываются офлайн.
4. Студия на ноутбуке: загрузить картинку плана → «Распознать комнаты» → поставить двери → «Опубликовать» (ссылка та же).
5. Телефон организатора: снять видео комнаты → через минуту контур появляется в студии.
6. «Живой статус» кафе → «очередь» — у жюри на телефоне сразу меняется значок.
7. «Статистика»: что искали и не нашли.

## 6. Чек-лист для фронта

Всё ниже уже есть в схеме (`schemaVersion` 2) и в `@ttkpr/map-core`; типы и zod-схемы — в `@ttkpr/api-client`. Без новых полей карта выглядит и строит маршруты как раньше, так что пункты можно делать по одному.

**План и 3D (viewer `PlanMap.tsx`, studio `EditorMap.tsx`)**
- [ ] Стены 3D: добавить `"fill-extrusion-base": ["get", "base"]` к слою стен — `wallFeatures` отдаёт `base`/`height`/`kind`, окно становится подоконником и перемычкой.
- [ ] Мебель 3D: источник из `fixtureFeatures(bundle, levelId)`, слой fill-extrusion по `height`/`base`, цвет — `color` или `FIXTURE_COLORS[kind]`.
- [ ] Зоны и мебель 2D: `addSource(SOURCE.zones | SOURCE.fixtures)` из `toCollections`, слои `detailLayers(levelId)` перед слоем дорожек; при смене этажа — `setFilter` и для `DETAIL_LAYERS`. В студии — `setData` новых коллекций.
- [ ] 3D-макет (`Dollhouse.tsx`): `wallSegments` → `wallPieces` (куски с `base`/`top`), чтобы окна стали проёмами.

**Посетитель**
- [ ] Карточка места: `placeOf` («Зал A · Фудкорт»), `photos`, `links`, `contacts` (Telegram → `https://t.me/<имя>`), `hours`, `tags`, переводы `localized(poi, lang)`.
- [ ] События места: `eventsAt(bundle).byPoi`, подписи `eventWhen` / `formatEventTime(ref, venueTimeZone(bundle))`, бейдж «идёт сейчас».
- [ ] Карточка помещения по тапу (`unitAt`): описание, фото, вместимость, удобства (`amenityLabel`, `amenityEmoji`), часы, пометка «служебное».
- [ ] «Программа дня» и «Сейчас идёт»: `daySchedule`, `eventStatus`; перерисовка по таймеру `nextTimeChange`.
- [ ] Объявления: баннер `activeAnnouncements`, нажатие открывает `poiId`.
- [ ] Брендинг: `venue.branding.accentColor` → CSS-переменная акцента, текст на кнопках `textOn(accent)`, приветствие `welcomeTitle`/`welcomeText`.
- [ ] «Главное»: POI с `featured`.
- [ ] Язык: `venueLanguages`, `pickLanguage(bundle, navigator.languages)`, `languageName`.
- [ ] Поиск (`viewer/lib/search.ts`): индексировать `searchEntries(bundle, { lang })` с полем `keywords`; у помещений и зон есть `position` для маршрута.
- [ ] Свои категории: `categoryOf(bundle, id)` / `poiCategories(bundle)` вместо `categoryLabel`/`categoryEmoji`.
- [ ] «Без ступенек»: в объяснение «маршрут не найден» добавить «или вращающиеся / узкие двери».
- [ ] Живые статусы: опрос `GET /api/public/maps/{slug}/live.json` раз в 30 с, только пока вкладка видна; значок на точке и в карточке.

**Студия**
- [ ] Инструменты «Окно», «Мебель», «Зона»; новые id — `newId("f")`, `newId("z")` (формат `^[A-Za-z0-9][A-Za-z0-9._:-]{0,63}$`).
- [ ] Свойства: доступ и тип дверей, высота и цвет помещения, удобства, часы, фото, ссылки, контакты, события, брендинг, объявления, свои категории, языки и переводы.
- [ ] Очищенное текстовое поле отправлять как `null` (в zod у строк `min(1)`).
- [ ] Ошибки проверки с типом `map_*`: в `fieldMessage` (`studio/lib/api.ts`) показывать `msg` — там готовый русский текст.
- [ ] Живой статус места: переключатель «открыто / очередь / занято / закрыто» (`PUT /api/maps/{id}/live/{poiId}`).
- [ ] Съёмка видео: MediaRecorder + дорожка ориентации → панорама (`POST /api/maps/{id}/panoramas/video`) или скан комнаты (`POST /api/maps/{id}/scans`); результат скана — контур, который ставится на план.

**Демо.** События демо-площадки привязаны к сегодняшней дате по Москве: в день показа пересобрать демо (`uv run --package worker python -m worker.demo`).
