Ты отвечаешь за обе стороны конвейера панорам: съёмку в мобильном браузере и склейку на сервере. Это самая рискованная часть проекта: главное — надёжный результат на реальных интерьерах с белыми стенами. Перед работой прочитай `CLAUDE.md` (соглашение по кватернионам) и раздел «Панорамы» в `docs/ARCHITECTURE.md`.

## Съёмка (apps/studio, экран Capture)

- Одна кнопка «Начать съёмку» запрашивает и камеру, и `DeviceOrientationEvent.requestPermission()` (iOS). Всё только по HTTPS.
- Камера: `getUserMedia({ video: { facingMode: 'environment', width: { ideal: 3840 }, height: { ideal: 2160 } } })`. Android — `ImageCapture.takePhoto()`, если доступен; иначе кадр из видео. На iOS ориентация экрана не блокируется — UI под портрет.
- Ориентация: `deviceorientation` (+ `screen.orientation.angle`) → кватернион «камера → мир» в конвенции OpenCV. Конвертация — одна функция с юнит-тестами на известные позы.
- Автоспуск: прицел в пределах ~3° от цели и угловая скорость ниже порога ~150 мс. Резкость — дисперсия Лапласиана на уменьшенном кадре в Web Worker / OffscreenCanvas.
- Сетка целей зависит от оценки FOV; FOV уточняется после склейки и запоминается для устройства.
- Wake Lock на время съёмки. Подсказки: вращать вокруг объектива, не сходить с места, держать на уровне глаз.
- Кадры (JPEG ~0.9, длинная сторона ≤ 2560) + метаданные → IndexedDB → загрузка по presigned URL с повторами. Съёмка не теряется при обрыве сети или перезагрузке.
- Живой предпросмотр покрытия на сфере по датчикам (three.js). Холст ≤ 4096×2048 (лимит iOS).

## Склейка (apps/worker)

1. Начальные повороты из датчиков, начальный фокус из оценки FOV.
2. Пары для сопоставления — только с перекрытием по датчикам.
3. SIFT на кадрах ~1000–1500 px (опция: ALIKED + LightGlue на GPU). RANSAC по модели чистого поворота.
4. Свой bundle adjustment (`scipy.optimize.least_squares`): лучевые ошибки по совпадениям + взвешенный штраф за отклонение от датчиков. Пары без совпадений держатся на датчиках.
5. Горизонт — по гравитации. Варп в equirect, экспокомпенсация, graph-cut швы, multi-band blending (cv2.detail).
6. Надир — inpaint или логотип. Выход 8192×4096.
7. Отчёт о качестве: число совпадений по парам, остаточная ошибка, кадры «на датчиках» — показывать организатору, если результат сомнительный.

Для сравнения держи скрипт с Hugin CLI (`pto_gen` → `pto_var` с углами датчиков → `cpfind --prealigned` → `autooptimiser -a -m -l -s` → `nona`/`enblend`).

## Импорт и тайлы

- Готовая панорама: проверка 2:1, чтение GPano XMP (частичные сферы дополняются до полной).
- Всё через pyvips: перекодирование (без EXIF/GPS), превью 512 px, уровни 2048/4096/8192, тайлы 512 px WebP. Пути с хешем, `immutable`.

## Тестовые данные

- Держи набор реальных съёмок (минимум одна комната с белыми стенами и одна с повторяющейся текстурой) и регрессионный скрипт: склеить всё и сохранить превью для сравнения глазами.
