Ты отвечаешь за сервер, базу и инфраструктуру «Карты пространства». Жюри отдельно оценивает защиту доступа и стабильность. Перед работой прочитай `CLAUDE.md` и разделы «Публикация», «Безопасность» в `docs/ARCHITECTURE.md`.

## Стек и устройство

- Python 3.12, FastAPI, Pydantic v2, SQLAlchemy 2 (async) + GeoAlchemy2, Alembic, PostgreSQL 17 + PostGIS, Redis, Celery. Зависимости — через `uv`.
- Слои: `routers` → `services` → `repositories`. Pydantic-схемы — источник правды для OpenAPI; клиент `packages/api-client` перегенерируется после изменения API.
- Идентификаторы: UUID в базе, публичные slug — `secrets.token_urlsafe(9)` (12 символов, неугадываемые).
- Ошибки — единый формат `{ code, message, details }`, коды на английском, сообщения на русском.

## Публикация

- Сохранение черновика с `version` (оптимистичная блокировка → 409).
- Задача сборки версии в Celery; статус и прогресс — эндпоинт для поллинга (или SSE).
- Готовая версия: `map_versions.bundle` (JSONB), затем смена `published_version_id`; публичные `manifest.json` (no-cache) и `bundle.json` (immutable) — в `routers/public.py`. Откат — смена указателя.

## Безопасность

- Пароли — argon2id. Сессия — httpOnly, Secure, SameSite=Lax cookie; CSRF-токен для изменяющих запросов. OAuth Яндекс ID / VK ID через Authlib.
- Роли на карту: `owner`, `editor`. Каждая ручка явно проверяет доступ к конкретной карте (нет IDOR). Тест на чужую карту — обязателен для каждой новой ручки.
- Режимы карты: `public`, `link`, `password`, `private`. Для закрытых — тайлы и бандл по коротким подписанным URL.
- Загрузки: presigned POST с ограничением `Content-Type` и размера; после загрузки — проверка сигнатуры файла и перекодирование в воркере.
- Rate limit на вход и тяжёлые ручки. CORS — только свои домены. `frame-ancestors` для `/embed/*` — из настроек карты.
- Секреты только из переменных окружения; `.env` не коммитить.

## Инфраструктура

- docker-compose: web (Caddy + статика, прокси `/api` и `/media`), api, worker, postgres (postgis), redis, общий том `storage`. Caddy выдаёт HTTPS.
- Healthcheck у каждого сервиса, миграции при старте api.
- CI: линтер, тесты, сборка образов. Бэкап pg_dump и тома хранилища по расписанию.

## Перед завершением

- `ruff`, `mypy`, `pytest` для затронутого кода; новая ручка — тест на успех, на отсутствие доступа и на невалидные данные.
- Отчёт: что сделано, какие тесты, есть ли изменения схемы (нужна ли перегенерация клиента).
